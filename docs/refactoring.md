# SpeakLoop: переделка в голосовой тренер диалога (v1)

Статус: утверждённый порядок работ, детали отдельных этапов ещё открыты (см. раздел 10).
Дата: 2026-09-11.
Основная копия файла: `docs/refactoring.md` в репозитории SpeakLoop.

Документ заменяет `docs/SpeakLoop-v1-plan.md`. Исходные данные для него:
`docs/SpeakLoop-status-2026-09-11.md` (разбор текущего кода) и
`docs/Mimora-reuse-inventory.md` (что можно взять из Mimora).

---

## 1. Цель

SpeakLoop становится голосовым тренером диалога для личной системы изучения языков.
Урок ведётся по промпту free-talk (`language-teacher/tmp/PROMPT-free-talk-2026-09-10.md`).
Ученик говорит голосом или пишет текст, модель отвечает в формате NOTE / SAY / SUMMARY:

- `NOTE:` исправление, только на экран;
- `SAY:` реплика партнёра, озвучивается;
- `SUMMARY:` итог урока по команде «finish», только на экран.

Технические задачи, уже решённые в Mimora (запуск llama-server, запись и
воспроизведение звука, TTS, установка, пути, настройки), не решаются заново:
код копируется из Mimora и адаптируется.

## 2. Исходное состояние (v0)

Настольное приложение на Tkinter. Модули в корне: `main.py`, `config.py`, `stt.py`,
`llm.py`, `tts.py`, сервер модели `llm_server/` (FastAPI + llama-cpp-python).

### 2.1. Что умеет v0 (это поведение сохраняет этап 1)

- Окно «Emma - Voice Tutor»: чат (строки You / Emma / [System]), круглая кнопка
  микрофона с 5 состояниями (loading, idle, recording, processing, speaking),
  строка статуса со временем STT и LLM в миллисекундах.
- Загрузка при старте: Whisper и Kokoro, затем сервер модели (или проверка LM Studio),
  затем прогрев STT и TTS.
- Запись: пока удерживается Space или кнопка мыши; не дольше 20 с; короче 0,2 с
  отбрасывается с сообщением; выравнивание громкости по пику (порог 0,01, уровень 0,9).
  Это единственный пункт, который этап 1 меняет: с шага 1e запись начинается
  одним нажатием и заканчивается по тишине (см. 6.5).
- Распознавание: faster-whisper small, язык `en`, beam 1, порог тишины 0,45,
  начальный промпт; пустой результат даёт сообщение «Could not hear you clearly».
- Модель: llama-3.2-3b-instruct Q4_K_M, персона Emma (русский -> английский),
  temperature 0,3, top_p 0,9, max_tokens 50, история 4 пары реплик, ответ потоком
  появляется в чате.
- Озвучка: Kokoro (`a`, голос `af_heart`), по предложениям, но только после конца
  ответа модели (приём с sentinel против конкуренции за GPU); на Windows через winsound.
- Прерывание: начало записи останавливает озвучку.
- Варианты подключения модели: `local_server` (порт 8765, 20 слоёв на GPU,
  контекст 2048, ожидание 60 с) и `lm-studio` (`http://localhost:1234/v1`).
- ESC и закрытие окна завершают приложение и сервер модели.
- Логи: `voice_tutor.log`, `llm_server.log` в корне.

### 2.2. Известные проблемы и где они решаются

| # | Проблема | Шаг |

| 2 | Ошибка модели не видна: в чате пустая строка «Emma:» | 1c |
| 3 | Поток ответа не закрывается при прерывании, сервер продолжает генерацию | 1c |

## 3. Принятые решения

- **Заимствование:** нужные модули Mimora копируются в SpeakLoop и адаптируются.
  Общей библиотеки нет, SpeakLoop не становится режимом Mimora.
- **Интеграция:** v1 самостоятельная. Шапка урока вводится в приложении, транскрипт
  сохраняется в файл. Договорённость с language-teacher (реестр, разбор транскриптов)
  позже.
- **Поведение урока:** промпт free-talk как есть, LESSON ARC остаётся в промпте.
  Программа разбирает NOTE / SAY / SUMMARY и даёт кнопки команд. Программа-ведущий
  урока и «бюджет непонимания» позже, но дизайн оставляет для них место.
- **Модель:** основная Gemma-4-12B-QAT (с этапа 2).
- **Языки v1:** английский и испанский, как в Mimora. Kokoro хорош только для
  английского, для испанского используется Supertonic.
- **Платформы:** Windows, Linux и macOS.
- **LM Studio** остаётся вторым вариантом подключения модели (как в Mimora).
- **Интерфейс:** ttkbootstrap, фасад окна с методами `enter_*` (как в Mimora).
- **Модели GGUF:** в `models/` (умолчание Mimora).
- **Определение железа** (`detect_hardware`) берётся вместе с установкой.
- **Модель spaCy для Kokoro** не ставится установщиком: misaki сам скачает её при
  первой озвучке на английском.
- **Порядок работ:** контролируемая последовательность этапов, каждый этап и шаг
  заканчивается рабочей версией. Этап 1 разбит на шаги (вариант B).
- **Проверки установки:** сначала в текущем `.venv`, потом окружение пересоздаётся с нуля.

## 4. Правила выполнения

1. Каждый шаг заканчивается приложением, которое запускается и работает.
   Поведение меняется небольшими шагами.
2. У каждого шага есть список проверки. Шаг закрыт, когда владелец проверил
   приложение по этому списку.
3. Код и тесты пишет Claude без запуска. Тесты и приложение запускает владелец.
4. Перед изменением существующих файлов Claude описывает изменения и получает
   разрешение.
5. Операции git (add, rm, mv, commit) и удаление файлов выполняет владелец.
   Каждый шаг заканчивается списком файлов на удаление.
6. В конце каждого шага `AGENTS.md` и `README.md` описывают текущий код.
7. Код, комментарии, логи и сообщения в коде на английском (ASD-STE100).
   Этот документ на русском по просьбе владельца.
8. Импорты внутри `speakloop/` абсолютные (`from speakloop import config`), как в Mimora.
9. Модули скачивания и `detect_hardware` не импортируют `config`
   (правило Mimora: `config` отключает сеть, когда модели скачаны).

## 6. Этап 1: перенос на код Mimora

Цель этапа: то же поведение v0 (раздел 2.1), та же модель llama-3.2-3b, та же
логика, но код из Mimora и новая структура каталогов. Одно исключение: режим
записи меняется на шаге 1e (решение 2026-09-12, см. 6.5).

| Шаг | Что меняется | Что работает после шага |
|---|---|---|
| 1a | Установка и зависимости | `python install.py` ставит всё; старое приложение работает как раньше |
| 1b | Каркас пакета, старый код переезжает в пакет | То же приложение через `python main.py` и `speakloop` |
| 1c | llama-server и LM Studio из Mimora | То же приложение на llama-server |
| 1d | Интерфейс на ttkbootstrap | То же приложение, новое окно |
| 1e | Звук и TTS из Mimora, языковые профили | То же приложение, гонка прерывания исправлена |

Интерфейс (1d) идёт раньше звука (1e): после разделения на контроллер и окно замена
звука затрагивает только контроллер. llama-server (1c) идёт раньше интерфейса, потому
что бинарник и GGUF уже ставит установщик из 1a, а шаг небольшой.

### 6.1. Шаг 1a: установка и зависимости

**Новые файлы:**

- `pyproject.toml` по образцу Mimora:
  - `name = "speakloop"`, версия из `speakloop/__init__.py`;
  - `requires-python = ">=3.11,<3.13"` (с тем же обоснованием, что в Mimora);
  - `license = "MIT"`;
  - поиск пакетов `include = ["speakloop*"]`, `namespaces = false`
    (старые модули в корне не попадают в пакет);
  - `[project.scripts]` добавляется на шаге 1b, когда появится `cli.py`.
- Зависимости (метки платформ и обоснования версий переносятся из Mimora):
  - ядро: numpy (<2.5; для Intel Mac <2), torch (для Intel Mac 2.2.2),
    transformers (>=5.3; для Intel Mac <5), numba (ограничение только для Intel Mac);
  - звук: soundfile, sounddevice, librosa (пересэмплирование в `recorder`), scipy;
  - распознавание: faster-whisper (новая);
  - синтез: kokoro, supertonic;
  - модель: openai;
  - скачивание: huggingface_hub (>=1.24, кроме Intel Mac), click;
  - интерфейс: ttkbootstrap (<2), pillow.
- Не переносятся: phonemizer-fork, espeakng-loader, panphon, python-Levenshtein,
  fastdtw, sentencepiece, protobuf, wordfreq, scikit-learn (нужны только оценке
  произношения и переводчику Mimora), пин `spacy>=3.8,<3.9` (без своего модуля
  скачивания spaCy не нужен). Из старого SpeakLoop уходят keyboard и llama-cpp-python.
- `speakloop/__init__.py`: `__version__`.
- `speakloop/bootstrap.py`: из Mimora (нужен `detect_hardware` для заголовка лога).
- `speakloop/paths.py`: из Mimora; переменная `SPEAKLOOP_HOME`, имена каталогов
  `SpeakLoop` / `speakloop`; из путей убирается `spacy_model_dir`.
- `speakloop/loader.py`: из Mimora.
- `speakloop/models_info.py`: записи KOKORO, WHISPER_SMALL
  (`Systran/faster-whisper-small`), SUPERTONIC, GGUF_CHAT (llama-3.2-3b, как сейчас).
  Размер скачивания Whisper измеряет владелец через `tools/measure_model_sizes.py`.
- `speakloop/model_fetch.py`: из Mimora; репозитории HF: Kokoro и Whisper;
  скачивание Supertonic остаётся; Wav2Vec2 и NLLB убираются.
- `speakloop/gguf_fetch.py`, `speakloop/llama_server_fetch.py`: из Mimora
  (закреплённый релиз llama.cpp с sha256, проверки `--version` и `--list-devices`).
- `speakloop/detect_hardware.py`: из Mimora. Изменение: `WAV2VEC2_DEVICE` заменяется
  на `STT_DEVICE`, который проверяется через ctranslate2 (библиотека faster-whisper),
  а не через torch. Правила для контекста и слоёв GPU пока как в Mimora
  (пересматриваются на этапе 2).
- `install.py`: из Mimora, урезанный. Порядок:
  - предварительно: проверка venv, VC++ Redistributable (Windows), tkinter и
    PortAudio (Linux);
  - 1: версия Python;
  - 2: поиск GPU через nvidia-smi;
  - 3: CUDA-сборка torch;
  - 4: зависимости из `pyproject.toml`;
  - 5: модели HF (Kokoro, Whisper) в `model_cache/`;
  - 6: веса Supertonic;
  - 7: бинарник llama-server в `bin/llama/`;
  - 8: GGUF в `models/`;
  - 9: определение железа, `config/hardware_config.json`;
  - 10: ярлык `run_speakloop.bat` или `run_speakloop.sh`.
  - Флаги как в Mimora: `--yes`, `--dry-run`, `--reinstall`, `--cpu`, `--gpu`,
    `--skip-models`, `--skip-gguf`, `--skip-llm`. Лог: `logs/install.log`.
  - Убираются шаги espeak-ng и spaCy.
- `tools/measure_model_sizes.py`: из Mimora, адаптированный.
- `tests/`: адаптированные тесты Mimora для `paths`, `loader`, `models_info`,

**Изменяемые файлы (с разрешения владельца):**

- `.gitignore`: добавить `logs/`, `model_cache/`, `bin/`, `config/settings.json`,
  `config/hardware_config.json`, `run_speakloop.*`.
- `README.md`: раздел установки (`python install.py`, ручная установка,

**Старый код** (`main.py`, `config.py`, `stt.py`, `llm.py`, `tts.py`, `llm_server/`)

### 6.3. Шаг 1c: llama-server и LM Studio

**Что делается:**

- `speakloop/llm_server_ctl.py`: из Mimora. Флаги `--ctx-size`, `--parallel 1`,
  `--cache-reuse 256`, `--api-key`, `--no-ui`; проверка `--list-devices` перед
  запуском; безопасная остановка из двух потоков.
- `config.py`: ключи `llm_backend` (`llama-server` | `lm-studio`),
  `llama_server_path`, `lm_studio_host`, `external_model_path`, `external_n_ctx`,
  как в Mimora. Вариант `off` не нужен (диалог без модели невозможен).
- `speakloop/llm.py` остаётся своим (в Mimora `llm.py` генерирует фразы, а здесь
  нужен диалог с историей и потоком), но:
  - поток ответа закрывается при прерывании (проблема 3);
  - ошибка модели показывается в чате и в статусе (проблема 2).
- Приём с sentinel остаётся: llama-server и Kokoro по-прежнему делят один GPU.
- Проблема 4 (сервер живёт после падения приложения, порт занят) решается
  проверкой порта перед запуском (в Mimora этого нет, решение своё):
  - порт свободен: обычный запуск, как описано выше;
  - на порту отвечает сервер: он используется как есть и не останавливается при
    выходе. Модель, контекст и число слоёв у него те, с которыми его запустили,
    поэтому в чат идёт сообщение, а в лог предупреждение, список моделей
    (расхождение с `external_model_path` тоже предупреждение) и размер
    контекста из `/props` llama.cpp (контекст меньше `external_n_ctx` тоже
    предупреждение). Обе проверки только диагностика: отвечающий сервер из-за
    них не отклоняется;
  - порт занят программой, которая не отвечает по API: второй сервер не
    запускается, приложение сообщает, что порт занят.
  Остановка чужого сервера не делается: приложение не знает, кто его запустил.
- Причина отказа запуска передаётся в окно полем `last_error` контроллера,
  сообщение в чате называет `logs/main.log` и `logs/llm_server.log`.
- Тесты: `llm_server_ctl`, `llm` (разбор текста ошибки).

**Проверка:**

- приложение запускает llama-server с `models/llama-3.2-3b-instruct-q4_k_m.gguf`;
- в логе есть результат `--list-devices` с CUDA;
- после аварийного завершения приложения следующий запуск работает: старый сервер
  используется как есть, в чате об этом сообщение, в логе его модель и контекст;
- когда порт 8765 занят посторонней программой, сообщение называет порт;
- при `llm_backend = "lm-studio"` приложение работает с запущенным LM Studio;
- при остановленном сервере ошибка видна в чате;
- все пункты раздела 2.1 работают.

**На удаление:** `llm_server/` целиком.

### 6.5. Шаг 1e: звук, TTS и языковые профили

**Что делается:**

- `speakloop/audio_io.py`, `speakloop/recorder.py`, `speakloop/playback.py`: из Mimora.
  `playback.py` взят урезанным: только жизненный цикл stop-события (лица и
  анимации в SpeakLoop нет). Из `recorder.py` не переносятся диагностические
  дампы (`save_recordings`, `logs/records/`).
- Режим записи (решение 2026-09-12 по вопросу 10.2): одно нажатие Space или
  кнопки начинает запись; запись заканчивается сама после паузы
  (`silence_timeout`), по повторному нажатию или по пределу времени.
  Отпускание клавиши только снимает защиту от автоповтора. Это единственное
  осознанное отступление от поведения v0 внутри этапа 1.
- Новые ключи настроек: `silence_timeout`, `silence_threshold`, `accent`,
  `voice`. Ключа выбора языка нет.
- `speakloop/tts.py`: из Mimora; варианты синтеза Kokoro и Supertonic, свойство
  `sample_rate`, winsound на Windows и sounddevice на остальных платформах.
- `speakloop/languages/`: шаблон профилей Mimora, но свой формат:
  - `display_name`;
  - `whisper_language` (`en`, `es`);
  - `default_variant` и `variants`: вариант синтеза (`kokoro` / `supertonic`),
    код языка, голоса, голос по умолчанию;
  - `tts_warmup`: фраза для прогрева.
  - english: варианты american (`a`, `af_heart`) и british (`b`, `bf_emma`);
  - spanish: вариант castilian (Supertonic, `es`, голоса F1..F5, M1..M5).
- `speakloop/stt.py`: язык распознавания из профиля.
- Язык на этом шаге фиксирован: английский. Выбор языка включается на этапе 3.
- Исправляется гонка прерывания (проблема 1). Замер 2026-09-12: при старте записи
  во время озвучки поток записи ждал `config.AUDIO_LOCK` 0,46 с, и из 0,98 с
  удержания кнопки записалось только 0,448 с, то есть начало фразы пропало.
  Лечится двумя частями:
  - ожидание замка: путь winsound больше не берёт `config.AUDIO_LOCK` (winsound
    не трогает PortAudio), а сброс PortAudio делается только на Windows и только
    когда открытых потоков нет (`audio_io.py`);
  - потеря прерывания: stop-событие теперь своё на каждую реплику
    (`playback.py`), его никто не сбрасывает, и очередь TTS получает его вместе
    с меткой конца реплики. Запись, начатая во время распознавания прошлой
    фразы, не теряется: обмены выполняются по очереди под замком, а прошлый
    обмен быстро освобождает его, потому что его событие уже выставлено.
- Кнопка микрофона получает живой уровень входа: `set_record_level(level)` из
  Mimora рисует красный диск от радиуса 10 до внутреннего радиуса по RMS
  (`_MIC_LEVEL_FULL_RMS = 0.08`). Уровень приходит из `recorder.py`, а не
  считается в контроллере (решение 2026-09-12: делать здесь, а не в 1d, чтобы не
  писать свой источник уровня дважды).
- Тесты: `tts` (с заглушками), `recorder` (с заглушкой звукового потока),
  профили языков, новые ключи в `test_config`.

**Проверка:**

- Space во время распознавания прошлой фразы не теряет запись и не ломает прерывание;
- запись, начатая во время озвучки, не теряет начало фразы;
- запись заканчивается сама примерно через `silence_timeout` после последнего
  слова, а пауза перед первым словом её не обрывает;
- во время записи кнопка показывает уровень входа, в тишине диск не исчезает;
- озвучка без щелчков, прерывание работает;
- на Linux и macOS звук работает через sounddevice;
- все пункты раздела 2.1 работают.

**На удаление:** нет (старый `tts.py` заменён внутри пакета).

## 11. Риски

- **Шаблон чата Gemma:** системная роль через llama-server может не работать как
  ожидается. Проверка на этапе 2.
- **Whisper исправляет грамматику ученика** до того, как её увидит модель, и тогда
  NOTE не находит ошибок. Проверка на этапе 3.
- **CUDA для faster-whisper:**
  - Windows: библиотеки cuBLAS и cuDNN, порядок импорта torch;
  - Linux: поиск тех же библиотек;
  - macOS: только CPU;
  - Intel Mac: нужно проверить наличие колёс ctranslate2.
- **VRAM:** Gemma 12B с контекстом 16384 плюс Whisper и Kokoro на одном GPU.
  На слабых картах частичная выгрузка слоёв сильно замедлит ответы.
- **Длинный промпт** (около 2300 токенов): системный промпт должен быть стабильным,
  иначе кэш префикса не работает.
- **spaCy** скачивается при первой озвучке на английском: нужны сеть и pip
  в окружении (не работает при установке через `uv tool`).
- **Установка в текущий `.venv`** может сдвинуть версии torch и numpy и затронуть
  старый llama-cpp-python до шага 1c.
- **Веса Supertonic** под лицензией OpenRAIL-M: скачиваются, в репозиторий не кладутся.
