## 1. Исходные данные: что показали логи

Просмотрены `logs/main.log`, `logs/llm_server.log` и 27 транскриптов уроков с
бэкендом llama-server и моделью Gemma 4 12B QAT Q4_0 (2026-10-02 ... 2026-10-10).
Уроки через LM Studio в подсчёт не вошли.

### 1.1. Скорость (RTX 3090)

- Prefill около 2900 t/s, генерация около 86 t/s.
- Короткий ответ модели приходит за 0.3-0.6 с.
- Урок занимает около 2.4 тыс. токенов при контексте 16384.
- Вывод: большой запас по задержке. Его можно потратить на второй запрос к
  модели за ход или на модель крупнее.

Попутная находка: в `llm_server.log` есть строка
`cache_reuse is not supported by this context, it will be disabled`. С Gemma ключ
`--cache-reuse 256` фактически не работает. Вреда нет, пользы тоже.

### 1.2. Ошибки модели

**1. Исправления, которые промпт запрещает (главная проблема).**
Из примерно 20 строк NOTE соответствуют правилам промпта только 2-3.

- Исправление совпадает с исходной фразой: `"I am a C++ programmer." -> "I am a C++ programmer."`,
  `"I want to order coffee." -> то же`, `"five times a week" -> то же`.
- Артикли: `daily meeting -> a daily meeting` (дважды), `the poker -> poker`,
  `SC Plus Plus programmer -> a C++ programmer`.
- Время и форма глагола: `I am working -> I work` (дважды), `I am wake up -> I wake up`,
  `like to watch -> like watching`, `so many freedom -> as much freedom`.
- Предлоги: `in the train -> on the train`.
- Догадки, которые промпт запрещает строже всего: `I like Bolton -> I like basketball`
  (дальше SAY продолжает про баскетбол), `I won't draw the coffee -> I don't draw coffee`
  (нужно было сказать, что фраза непонятна).
- Объяснение на два-три предложения вместо одного.

**2. NOTE на команды** (`finish -> I want to finish`, `new topic: ... -> Let's talk about ...`).
В одном уроке так на все 7 команд подряд. Защита в коде уже добавлена
(NOTE про команду убирается из окна, транскрипта и истории, случай пишется в лог).

**3. «finish» вызывает вопрос вместо итогов** («Do you want to finish now?», 3 урока).
По промпту вопрос нужен только для других слов («I'm tired», «goodbye»).

**4. SUMMARY.**
- Строки `SAY:` внутри итогов (урок 2026-10-10 00:47).
- Английский вместо русского: один урок полностью, ещё два частично.
- Цитата исправленной фразы как примера удачной (`one of my hobbies is DIY`).
- Выдуманное содержание («You mentioned that you want to change a habit»,
  когда ученик только переключал темы).
- Пустые пункты вида «Никаких исправлений не было» вместо пропуска пункта.

**5. SAY.**
- Общие утверждения и оценки: «Freelancing gives you a lot of freedom»,
  «Kiwi is a refreshing choice», «Poker is a card game».
- В ранних уроках дословный повтор фразы ученика. В последних почти нет.
- Подсказка на «hint» иногда почти полный ответ («I drink coffee. Do you drink coffee?»).

**6. Ошибка Whisper, не модели.** Три раза распознанный текст был
«The speaker is practicing simple phrases.». Это вторая фраза из
`WHISPER_INITIAL_PROMPT` в `config.py`: на тишине или шуме Whisper выдаёт подсказку
как распознанную речь.

### 1.3. Вывод из логов

Это не «простые ошибки» незнания языка. 12B-модель не держит длинный список
запретов (не исправлять артикли, время, предлоги, не угадывать). Нарушения
сосредоточены в правилах исправлений и в SUMMARY.

## 2. Роли частей системы (решение)

| Часть | Роль |
|---|---|
| Набор скилов для модели по подписке | Методист и учитель «за кадром»: память об ученике, оценка, создание уроков, разбор ошибок |
| SpeakLoop | Только живой разговор. Ничего больше |
| Mimora | Тренировка произношения |

Обоснование: планирование и анализ требуют ума, но не скорости, поэтому они у
сильной модели. Разговору нужна скорость, но меньше ума, поэтому он у локальной.

Полной связки пока нет. Формат jsonl транскрипта был сделан как раз под эту
задачу. Входом для урока предполагалось сделать промпт, который правится под
конкретный урок (раздел 6 предлагает другой способ).

## 3. Общие принципы

1. **Модель не учитель, а актёр.** Урок ведёт программа (этапы, таймеры,
   проверки), модель говорит реплики по короткой узкой инструкции.
2. **Всё, по чему программа может действовать сама, это поле, а не текст.**
   Свободного текста для модели минимум.
3. **Программа записывает наблюдения, а не оценки.** Оценивает учитель (скилы).
4. **Постоянный промпт, меняются только данные.** Только так можно честно
   сравнивать качество «до/после».
5. **Детерминированные проверки делает код** (использовано ли целевое слово,
   совпал ли повтор с образцом, есть ли кириллица), модель только там, где без
   неё нельзя.
6. **Более мощная модель помогает всегда**, но это очевидный путь, и он не
   является предметом этого документа.

## 4. Дообучение LoRA

### 4.1. С чем LoRA справляется

- Стиль и поведение: тон тьютора, длина реплик, разнообразие вопросов,
  удержание темы.
- Устойчивое соблюдение формата (NOTE / SAY / SUMMARY).
- Политика исправлений: что исправлять и что оставлять. Это именно тот тип
  ошибок, который показали логи, поэтому LoRA здесь подходит хорошо.

### 4.2. С чем справляется плохо

- Модель не станет «умнее»: незнание правила грамматики LoRA на нескольких
  сотнях диалогов почти не исправит.
- На узких данных возможна потеря общих способностей (catastrophic forgetting).
- Факты и рассуждения дообучением в основном не добавляются.

### 4.3. Практика для нынешнего стека

- Gemma 4 12B в режиме QLoRA (например, Unsloth) помещается в 24 ГБ (RTX 3090).
  Обучение на нескольких тысячах примеров: часы.
- Запуск: слить адаптер с весами и сконвертировать в GGUF, или отдавать адаптер
  отдельно (`llama-server --lora`).
- Модель сейчас QAT Q4_0. При обучении на bf16 и последующем квантовании выигрыш
  QAT частично пропадёт. Сравнивать качество нужно после квантования.
- LM Studio и упаковка программы скорее всего потребуют слитый GGUF.
- Каждая новая версия Gemma требует повторного обучения.

### 4.4. Данные

- Исправленные транскрипты jsonl (уже сохраняются).
- Эталонные ответы, размеченные сильной моделью по тому же промпту, с ручной
  проверкой. Перед этим проверить условия использования провайдера (у некоторых
  есть ограничения на обучение моделей на их ответах).
- Объём: 500-2000 примеров (фраза ученика с типичной ошибкой русскоязычного и
  правильный ответ тьютора).
- Лучший долгосрочный источник: скилы отмечают ошибки тьютора при разборе
  урока (раздел 12).

### 4.5. Оценка

Сложность высокая, эффект средний или высокий именно для политики исправлений.
Без набора для сравнения (раздел 13) эффект не измерить.

## 5. Быстрые меры для нынешней версии

Варианты от простого к сложному. Ни один не принят.

| # | Мера | Плюсы | Минусы |
|---|---|---|---|
| 5.1 | Защиты в коде: отбрасывать NOTE, где исправление совпадает с исходной фразой (после нормализации регистра и пунктуации); убирать `SAY:` внутри SUMMARY | дёшево, надёжно | закрывает только формальные случаи |
| 5.2 | Ниже temperature (сейчас 1.0, попробовать 0.6-0.7). Тему теперь выбирает программа, поэтому разнообразие от модели менее важно | одна константа | эффект не гарантирован, вопросы могут стать однообразнее |
| 5.3 | Грамматика GBNF через llama-server (поле `grammar` в запросе): не больше одного NOTE, форма `"..." -> "..."`, никаких `SAY:` в SUMMARY | формат гарантирован | только llama-server (у LM Studio только JSON schema), на смысл не влияет |
| 5.4 | Отдельный запрос на проверку исправления: основной промпт без раздела CORRECTIONS, второй короткий запрос «есть ли ошибка типа 1 или 2? Выведи NOTE или NONE» | короткие узкие промпты 12B держит лучше; на 3090 это ещё 0.3-0.5 с | на Mac M1 ход заметно медленнее, логика сложнее |
| 5.5 | Модель крупнее на 3090 (быстрый эксперимент) | лучше соблюдение правил | не помещается на Mac M1 16 ГБ |
| 5.6 | LoRA (раздел 4) | исправляет политику поведения | объём работы, поддержка |

Отдельно, вне модели:

- **Whisper initial prompt.** Убрать вторую фразу из `WHISPER_INITIAL_PROMPT` или
  отбрасывать результат, совпадающий с подсказкой.
- **`--cache-reuse` с Gemma не работает** (раздел 1.1). Раньше было решено ключ
  оставить. Вопрос можно пересмотреть.

## 6. Файл урока: вход от учителя

### 6.1. Почему не правка промпта под урок

| | Промпт, который учитель правит под урок | Файл урока (данные) + постоянный промпт |
|---|---|---|
| Контракт NOTE/SAY/SUMMARY | сильная модель может случайно сломать правила, от которых зависит разбор ответа в коде | правила не трогаются |
| Проверка до урока | нельзя, это свободный текст | проверка по схеме |
| Программа действует по плану | нет, план спрятан в тексте | да: этапы, целевые слова, счёт ходов |
| Нагрузка на 12B | весь план в одном длинном промпте | модель видит только текущий этап |
| Сравнение «до/после» | промпт каждый раз новый | промпт один |

Промпт к этому уже подготовлен: раздел LESSON ARC в `free_talk.md` начинается со
слов «A driver program can replace this section». Выбор темы программой (сделан
2026-10-10) это первый шаг в эту сторону.

### 6.2. Что готовит учитель

Пример файла (формат JSON или YAML не выбран, см. открытые вопросы):

```json
{
  "schema": 1,
  "lesson_id": "2026-10-12-a",
  "level": { "cefr": "A2", "max_words_per_sentence": 12, "speech_rate": 0.9,
             "wait_seconds": 10, "max_escalation": 4 },
  "goal": "Describe a past trip and ask about prices in a role-play",
  "learner_context": [
    "C++ programmer, works from home",
    "Lives in Asturias",
    "Hobby: woodworking"
  ],
  "targets": {
    "words": [
      { "text": "luggage", "ru": "багаж" },
      { "text": "delay", "ru": "задержка" }
    ],
    "structures": [
      { "id": "past_simple_irregular", "pattern": "went / took / bought",
        "example": "I took the train to Madrid." }
    ]
  },
  "correct_live": ["past_simple_irregular"],
  "stages": [
    { "id": "warmup", "type": "free_talk", "topic": "your last weekend",
      "max_turns": 3 },
    { "id": "main", "type": "free_talk", "topic": "a trip you remember",
      "elicit": ["luggage", "delay", "past_simple_irregular"], "max_turns": 8 },
    { "id": "roleplay", "type": "role_play",
      "situation": "Train ticket office in Oviedo",
      "tutor_role": "ticket clerk", "learner_role": "traveller",
      "learner_goal": "Buy a return ticket to Madrid for tomorrow morning",
      "hidden_info": "The morning train is full; only 14:30 has seats",
      "allow_model_answer": false,
      "max_turns": 8 }
  ],
  "notes_for_tutor": "Learner often drops past forms when telling stories."
}
```

### 6.3. Поля и зачем они нужны

| Поле | Назначение |
|---|---|
| `level` | программа сама подстраивает скорость TTS, длину фраз, таймауты проактивности |
| `goal` | одна фраза о цели урока, для модели и для отчёта |
| `learner_context` | 3-5 фактов об ученике, на которые модель опирается в вопросах |
| `targets.words` | 3-5 слов. Больше нет смысла: 12B не удержит, ученик за 10 минут не отработает |
| `targets.structures` | 1-2 конструкции с образцом |
| `correct_live` | только это исправляется в разговоре (мягко, повтором в SAY). Остальное записывается и уходит на разбор учителю |
| `stages` | 2-4 этапа. Переключает программа: по числу ходов, по команде ученика или по достижении цели |
| `elicit` | что вызвать у ученика. Если цель ещё не прозвучала, программа говорит модели: «следующий вопрос должен требовать слово delay» |
| `hidden_info` | в ролевой игре создаёт настоящий разговор: ученику надо договариваться |
| `allow_model_answer` | можно ли на этапе давать готовый образец ответа (раздел 8) |
| `notes_for_tutor` | одна-две фразы на случай, который в поля не укладывается |

### 6.4. Как программа использует файл

- Промпт = постоянная часть (роль, формат, правила) + короткий блок
  «THIS STAGE», собранный из полей текущего этапа. На новом этапе блок меняется.
- Целевые слова проверяет код (сравнение с учётом простых форм слова).
- Без файла урока программа работает как сейчас (тема из `first_topic` или
  случайная из списка).

## 7. Типы этапов урока

### 7.1. `free_talk`

Нынешний режим: тема и вопросы. Остаётся основой для разминки.

### 7.2. `role_play`

Ситуация, роли, цель ученика, скрытая информация. Программа проверяет, достигнута
ли цель (короткий запрос к модели «yes/no» или признаки в коде), и только потом
переходит дальше.

### 7.3. `scripted_roleplay`: готовый диалог как направление

**Идея.** Взять готовый диалог и воспроизвести его не один в один, а с
изменениями: диалог задаёт направление, но не точное задание.

**Оценка: высокая. Хорошо подходит для 12B и уровня A2-B1.** В методике это
схема «образец, потом вариация».

Плюсы:
- У разговора понятная цель и порядок. Модели проще держать сцену, чем свободную беседу.
- Нужные фразы появляются естественно.
- Ученик может заранее прочитать или послушать образец (в скилах).
- Одну сцену можно повторить 2-3 раза с растущими изменениями. По jsonl видно, как
  падает время раздумья и число подсказок. Это измерение прогресса.

Риски и как их снять:
- **Модель зачитывает диалог дословно.** Модели дают не текст диалога, а «ходы»
  (beats): шаг, цель шага, 1-2 ключевые фразы. Текст образца нужен только ученику.
- **Ученик уходит от сценария.** Ходы описывают цель, а не реплики, поэтому
  модель может вернуться к цели любым путём. Если ученик застрял, работает лестница
  подсказок.
- **Скучно повторять.** Изменения: другие детали (город, время, цена); осложнение
  (поезд полный, карта не проходит); **обмен ролями** (ученик играет кассира и
  вынужден задавать вопросы).
- **Авторские права.** Диалоги из учебников годятся только для личного
  использования. Для распространяемой программы образцы сочиняет сильная модель.

Пример этапа:

```json
{ "id": "roleplay", "type": "scripted_roleplay",
  "model_dialogue_ref": "dialogues/train-ticket-01.md",
  "tutor_role": "ticket clerk", "learner_role": "traveller",
  "beats": [
    { "goal": "learner asks for a ticket", "key_phrases": ["a return ticket to ..."] },
    { "goal": "clerk offers times, morning train is full", "key_phrases": ["fully booked"] },
    { "goal": "learner chooses another time and asks the price" },
    { "goal": "learner pays and asks about the platform" }
  ],
  "variation": { "details": "Madrid -> Bilbao", "complication": "card payment fails" }
}
```

Результат для учителя: какие ходы ученик прошёл сам, где понадобилась подсказка,
какие ключевые фразы использовал, сколько думал на каждом ходу.

### 7.4. `text_discussion`: обсуждение статьи

**Идея.** На основе статьи составить план обсуждения и использовать его как основу
диалога.

**Оценка: средняя или высокая для B1+, низкая для A2.**

Опасение «не будет полного контекста темы» не главная проблема: упрощённая статья
на 400-800 слов занимает 1-2 тыс. токенов и целиком помещается в контекст 16384
(урок сейчас около 2.4 тыс.).

Настоящие проблемы:
1. **Уровень.** Обычная статья для A2 слишком сложна. Учитель сначала делает
   упрощённую версию (graded reader).
2. **Ученик должен прочитать статью до разговора.** Это смысл упражнения (сначала
   вход, потом речь), но это отдельный шаг вне SpeakLoop.
3. **12B начинает читать лекцию** вместо вопросов. Нужны жёсткое правило в блоке
   этапа и лестница вопросов.
4. **Модель добавляет факты, которых нет в статье.** Модели дают список фактов и
   правило опираться только на них.
5. **Мнение требует уровня.** Лестница начинается с фактов.

Пример этапа:

```json
{ "id": "discussion", "type": "text_discussion",
  "text_ref": "texts/remote-work-simplified.md",
  "key_facts": ["...", "...", "..."],
  "targets_from_text": ["commute", "productivity", "isolation"],
  "question_ladder": [
    { "kind": "retell", "prompt": "Tell me in two sentences what the article is about" },
    { "kind": "fact", "prompt": "What problem did the workers have?" },
    { "kind": "personal", "prompt": "Is it the same for you?" },
    { "kind": "opinion", "prompt": "Would you go back to an office? Why?" },
    { "kind": "hypothetical", "prompt": "What would change if ..." }
  ] }
```

Результат для учителя: какие ключевые факты ученик назвал при пересказе, какие
слова из текста использовал, на какой ступени лестницы начались трудности (хорошая
мера уровня).

Сильная сторона: интересное ученику содержание и словарь из реального текста.

### 7.5. Сравнение двух идей

| | `scripted_roleplay` | `text_discussion` |
|---|---|---|
| Уровень | A2-B1 | B1+ (A2 только с сильным упрощением) |
| Насколько 12B справляется | хорошо (короткие ходы) | средне (склонна пересказывать) |
| Подготовка учителя | средняя | больше (упрощение, факты, лестница) |
| Шаг до урока | прочитать образец (по желанию) | прочитать текст (обязательно) |
| Мотивация | средняя (бытовые сцены) | высокая (свои темы) |
| Ценность результата | беглость в типовых ситуациях | понимание, словарь, уровень по лестнице |

Этапы можно сочетать в одном уроке: разминка, обсуждение статьи, ролевая игра по ней.

Предложение (не решение): начать с `scripted_roleplay`, потом `text_discussion`.

## 8. Проактивный тьютор и пауза

### 8.1. Идея

Программа не ждёт ответа бесконечно. После таймаута она повторяет вопрос, меняет
его, подсказывает, может полностью ответить за ученика и попросить повторить,
проверяет повтор, а позже задаёт тот же или похожий вопрос снова. Нужна кнопка
паузы.

**Оценка: высокая польза, средняя сложность, особого железа не требует.**
Так ведёт себя живой учитель.

### 8.2. Лестница ведёт код, а не модель

Таймеры и шаги держит программа (`root.after` в Tk, ложится в нынешнюю схему
потоков). Модель вызывается только для нового текста.

| Шаг | Когда (пример для A2) | Что происходит | Нужна ли модель |
|---|---|---|---|
| 0 | вопрос прозвучал | ожидание ответа | нет |
| 1 | ~10 с тишины | повтор вопроса медленнее | нет: готовое аудио или TTS с меньшей скоростью |
| 2 | ещё ~10 с | вопрос проще (как команда «simpler») | да |
| 3 | ещё ~10 с | подсказка: выбор из двух или первые слова (как «hint») | да |
| 4 | ещё ~10 с | образец ответа: «Try this: I went to Madrid by train. Now you say it.» | да |
| 5 | ученик повторяет | проверка повтора | нет: код сравнивает слова с образцом |
| 6 | через 2-3 хода | тот же или похожий вопрос снова | да |
| стоп | лестница пройдена, ответа нет | автоматическая пауза: «I'll wait. Press Space when you are ready.» | нет |

Шаги 2 и 3 уже существуют как команды simpler и hint, программа вызывает их сама.
Шаг 1 совпадает с запланированной кнопкой Repeat.

### 8.3. Что продумать

1. **«Думает» или «ушёл».** Любая речь по VAD (даже «э-э») сбрасывает таймер.
   Голосовая команда «wait» или «let me think» продлевает ожидание. Без
   автоматической паузы программа говорит в пустую комнату.
2. **Таймауты по ученику.** Начальное значение из `level.wait_seconds`, потом
   подстройка по реальному времени раздумья (медиана `latency_ms` из прошлых
   уроков, умноженная на коэффициент). Слишком быстрая лестница давит.
3. **Режим микрофона.**
   - Этап 1, нажатие на Space как сейчас. Таймер считает время от конца речи
     тьютора до нажатия. Проще, без эха, почти ничего не ломается. Ученик всё
     равно нажимает Space.
   - Этап 2, свободные руки. Микрофон открывается сам после речи тьютора.
     Настоящий разговор, но нужно не слышать тьютора в микрофон (микрофон закрыт,
     пока звучит TTS, или наушники), и нужны фильтры против «речи» Whisper в
     тишине: `no_speech_prob`, минимальная длительность речи, исправление
     initial prompt (раздел 5).
4. **Проверка повтора.** Нормализация текста (регистр, пунктуация) и доля
   совпавших слов с образцом (например, порог около 80%). Не совпало: одна
   повторная попытка, потом дальше по уроку. Без бесконечных кругов.
5. **Возврат к вопросу.** Очередь «долгов»: вопросы, на которые ученик ответил
   только после образца. Через 2-3 хода в блок этапа добавляется
   «ask again a question similar to: ...».

### 8.4. Пауза

- Кнопка «Пауза» и клавиша (например, P или Esc): остановить таймеры, оборвать
  речь тьютора, закрыть микрофон. В панели состояния: Paused.
- Продолжение: тьютор повторяет последний вопрос, лестница начинается сначала.
- Автоматическая пауза в конце лестницы.
- Обратный отсчёт в панели состояния (например, «Waiting · 7 s»), чтобы
  проактивность не была неожиданностью.
- Настройка: выключено / мягко / активно.

### 8.5. Связь с файлом урока

`level.wait_seconds`, `level.max_escalation`, `stage.allow_model_answer`
(например, в ролевой игре не давать готовый ответ, в разминке давать).

### 8.6. Решения по проактивности (2026-10-10/11)

Эти решения уточняют разделы 8.2-8.4. Где они расходятся, действуют решения
этого раздела.

**Общее**
- Начинаем с режима нажатия на Space (этап 1). Свободные руки позже.
- Нужны все шаги лестницы. Реализация делится на три шага P1, P2, P3 (ниже).
- Промпт можно менять по мере надобности (шаги 4 и 6).

**Настройки (`settings.json`)**
- `proactive`: `"auto"` (по умолчанию), `true`, `false`. `"auto"` включает
  проактивность, только если урок идёт по файлу задания (пока файла нет, значит
  выключено). Для проверки ставится `true`.
- `proactive_wait_seconds`: по умолчанию 10, одно значение для всех шагов.
- Базовая скорость речи тьютора: по умолчанию 1.0. Задаётся параметром `speed`
  при синтезе Kokoro.
- Скорость повтора: по умолчанию 1.0 (тогда шаг 1 звучит в том же темпе).
- Обе скорости это коэффициенты от нормальной речи. Пример: базовая 0.9, повтор
  0.75. Повтор растягивает сохранённое аудио на отношение повтор / базовая
  (0.75 / 0.9 ≈ 0.83).
- Имена ключей скоростей: `speech_speed`, `repeat_speed`. По умолчанию в коде
  1.0 и 1.0, у владельца и в примере настроек 0.9 и 0.8.

**Константы в коде**
- Порог совпадения повтора с образцом: 0.8.
- Через сколько фраз ученика возвращаться к вопросу-долгу: 3.

**Таймер**
- Запускается после того, как отзвучало последнее предложение SAY. Если ответ не
  озвучивается (только NOTE или ответ вне контракта), запускается, когда ответ
  показан.
- Не идёт: во время записи, пока модель думает, пока тьютор говорит, после
  SUMMARY, во время паузы и загрузки.
- Сброс на шаг 0: Space или кнопка микрофона, отправка фразы с клавиатуры, любая
  фраза ученика, нажатие клавиши в поле ввода (1a: A).
- Пустая запись (Whisper ничего не распознал) считается «нет ответа», таймер
  продолжает с текущего шага (1b: A).
- Потеря фокуса окна ставит паузу (1c: A).

**Ручные команды и лестница (9a: B)**
- Ручная команда сдвигает лестницу на свой шаг: после ручного simpler следующий
  шаг подсказка, после ручного hint следующий шаг образец.
- «new topic» сбрасывает лестницу на шаг 0. «finish» останавливает лестницу.

**Шаги**
- Шаг 1: один повтор. Повторяется только последнее предложение SAY (R3: A), из
  сохранённого аудио, на скорости повтора. В чат служебная строка, в историю
  модели ничего, в транскрипт событие `escalation`.
- Шаги 2-3: программа отправляет модели `simpler` / `hint`. В чате служебная
  строка (2a: B), в истории модели команда как есть, в транскрипте
  `source: "auto"`.
- Шаг 4: образец ответа через новую команду и новую строку контракта `MODEL:`
  (код берёт из неё точный текст образца).
- Шаг 5: повтор уходит модели как обычный ответ (5a: A). Код дополнительно
  считает совпадение слов с образцом и показывает результат ученику (5b).
- Шаг 6: вопрос, на который ученик ответил только после образца, становится
  долгом. Держится один долг. Через 3 фразы ученика программа добавляет к фразе
  команду `ask again: <question>`, модель задаёт тот же или похожий вопрос.
- Конец лестницы: автоматическая пауза. Фраза не звучит, в окне только
  состояние Paused (6a).

**Пауза**
- Кнопка Pause, клавиша P (только когда фокус не в поле ввода, как правило E3
  для Space), потеря фокуса окна.
- Если идёт запись, она отменяется без распознавания (7b).
- Если модель думает, ответ приходит и показывается, но не озвучивается (7c).
- Снятие паузы: P и кнопка повторяют вопрос (7d); Space и кнопка микрофона
  сразу открывают запись без повтора (изменено 2026-10-11 после проверки
  P1b). Лестница начинается с шага 0.

**Окно**
- В полосе состояния новые состояния Waiting и Paused.
- Обратный отсчёт виден только в последние 3 секунды перед шагом (8a).

**Транскрипт**
- P1: `escalation`, `pause`, `source: "auto"`, `schema` 2 в записи `meta`.
- P2: `model_answer`, `repeat_check`.
- P3: `retry`.

**Шаги реализации**
- **P1** (промпт и контракт не меняются): таймер и настройки, шаг 1 (повтор
  медленнее, базовая скорость и скорость повтора), шаги 2-3, автопауза после
  шага 3, пауза (кнопка, P, фокус окна), Waiting и Paused, обратный отсчёт,
  события P1 в транскрипте.
- **P2** (меняются промпт и `contract.py`): команда образца, строка `MODEL:`,
  шаг 4 перед автопаузой, шаг 5 с проверкой и отметкой ученику.
- **P3** (меняется промпт): очередь долгов, команда `ask again:`, событие
  `retry`.

**Отложено**
- R1 решён в начале P1: повтор замедляется, как в Mimora, понижением частоты
  воспроизведения (подробности в `proactive-tutor-spec.md`, раздел 6.6).
- 4', имя команды образца и нужна ли кнопка для ученика: решается в начале P2.

## 9. Результат урока: выход для учителя

Нынешний jsonl (запись `meta` и события `system`, `say`, `learner` и другие с
полями `ts`, `turn`, `text`, `llm_ms`, `tokens`, `source`) остаётся основой и
расширяется.

### 9.1. Новые поля в записи `learner`

| Поле | Смысл |
|---|---|
| `stage` | этап урока |
| `asr` | `avg_logprob`, `no_speech_prob` от faster-whisper: учитель отличает ошибку ученика от ошибки распознавания («I like Bolton», «IMSC++ Programmer») |
| `latency_ms` | время раздумья после конца речи тьютора |
| `speech_ms`, `words`, `pauses` | темп и беглость |
| `audio` | путь к файлу фразы (по желанию), его потом забирает Mimora |

### 9.2. Новые типы событий

| Тип | Смысл |
|---|---|
| `stage_start` / `stage_end` | этап и причина конца (`max_turns`, `goal_reached`, `learner_skip`) |
| `target_used` | слово или конструкция из плана, ход, цитата (проверяет код) |
| `target_elicited` | программа попросила модель вызвать цель |
| `lexical_gap` | «как сказать...» или русские слова в фразе (кириллица ищется кодом) |
| `live_correction` | какой recast дала модель и по какой цели |
| `repeat_request` | ученик попросил повторить |
| `interrupt` | ученик перебил тьютора |
| `escalation` | до какого шага лестницы дошло ожидание ответа |
| `model_answer` + `repeat_check` | образец, что сказал ученик, доля совпадения |
| `retry` | повторный вопрос: ответил ли сам и как быстро |
| `pause` | ручная или автоматическая |
| `beat_done` | ход сценария пройден (для `scripted_roleplay`) |
| `fact_covered` | ключевой факт назван при пересказе (для `text_discussion`) |

В запись `meta` добавляются `lesson_id` и признак файла урока (например, хеш),
чтобы связать транскрипт с планом.

### 9.3. Запись `lesson_end`

Считает код, детерминированно:
- какие цели использованы, какие нет;
- какие этапы пройдены, достигнута ли цель ролевой игры;
- доля времени речи ученика, средняя длина фразы;
- число команд, подсказок, образцов, пробелов в словах.

### 9.4. Что самое ценное для учителя (по порядку)

1. `lexical_gap`: точный список слов, которых не хватило.
2. Использованы ли цели: усвоено ли запланированное.
3. `latency_ms`, команды, `escalation`: где было трудно, даже если ответ вышел правильным.
4. `retry`: закрепилось ли то, что дали образцом.
5. Уверенность ASR: защита от ложных «ошибок».
6. Аудио: связь с Mimora.

### 9.5. SUMMARY от модели

По логам SUMMARY от 12B самая слабая часть. Варианты:

| Вариант | Суть | Плюс | Минус |
|---|---|---|---|
| A | Убрать SUMMARY. В конце урока программа показывает факты из `lesson_end` | точно, без ошибок | нет «человеческого» итога сразу после урока |
| B | Оставить только для ученика, учитель его не учитывает | ничего не меняется | ошибки в итогах остаются |
| C | Короткий итог по фактам: модель получает `lesson_end` и пишет 2-3 фразы по-русски только из них | живой текст без выдумок | ещё один запрос и ещё одно место для ошибки модели |

Склонность при обсуждении: A или C. Решение не принято.

## 10. Идеи для качества разговора

Оценки от 1 до 5. Сюда вошли идеи, относящиеся к разговорной части. Память об
ученике, оценка, планы и разбор ошибок остаются у скилов.

| Идея | Эффект | Сложность | Минимальное железо |
|---|---|---|---|
| Исправления в разговоре только recast в SAY и только по `correct_live` | 4 | 1 | любое |
| Команда «как сказать ...?»: вопрос по-русски посреди фразы, тьютор даёт слово и ждёт продолжения | 4 | 2 | любое |
| Время ожидания тишины в конце фразы по уровню, чтобы не обрывать думающего ученика | 3 | 1 | любое |
| Команды «повтори» и «медленнее» (Repeat уже в планах) | 3 | 1 | любое |
| Скорость и сложность речи по уровню, проверка слов в SAY по спискам CEFR, переформулировка при слишком сложных словах | 3 | 3 | любое |
| Ролевые сценарии с целью и проверкой цели | 4 | 3 | любое |
| Лестница подсказок в коде (выбор из двух, первые слова, слово по-русски) | 3 | 2 | любое |
| Проактивность (раздел 8) | 4 | 3 | любое |
| Сигналы усталости: ответы короче, паузы длиннее, больше «I don't know», и программа упрощает | 3 | 2 | любое |
| Постоянный персонаж тьютора (имя, характер, факты из `learner_context`) | 3 | 2 | любое |
| Картинки для описания (у Gemma 4 есть mmproj) | 3 | 3 | мощное |
| Потоковая озвучка, перебивание, короткие «mm-hm» | 4 | 4 | мощное (свободная память GPU) |
| Проверка целевых конструкций вторым запросом в реальном времени | 3 | 3 | мощное |
| Модель на 30B+ в разговоре | 4 | 1 (только железо) | очень мощное |
| Модель, которая слышит звук (omni), без отдельного STT. Пока скорее эксперимент: локальные варианты слабее связки Whisper + LLM | 3 (растёт) | 5 | очень мощное |

Идеи, которые принадлежат скилам или Mimora и здесь только для полноты: модель
ученика (ошибки, слова, интересы), интервальное повторение слов, оценка уровня,
отчёты о прогрессе, фонемный анализ произношения.

## 11. Уровни железа и сравнение с подпиской

### 11.1. Разговорная часть по уровням

| Уровень | Что реально | Плюс | Минус |
|---|---|---|---|
| Слабое (Mac M1 16 ГБ, ноутбук с 4 ГБ) | 12B по файлу урока, без исправлений в реальном времени, только recast; проактивность в режиме Space; всё остальное делают скилы после урока | полноценно работает | разговор попроще |
| Мощное (RTX 3090 24 ГБ) | то же плюс второй проход проверки целевых конструкций, потоковая озвучка с перебиванием, картинки, обучение LoRA | разговор живее, обратная связь сразу | сложнее код; у пользователей M1 этих функций не будет |
| Очень мощное (2×3090 / 48 ГБ+, Mac на 64-128 ГБ, 96 ГБ RAM с MoE-моделями) | модель 30-70B, несколько ролей параллельно (собеседник, корректор, методист), эксперименты с omni | план урока соблюдается почти идеально, вопросы разнообразнее | такое железо есть у немногих |

### 11.2. Сравнение подходов

| | SpeakLoop + скилы | Мощная локальная модель, просто чат | Голосовой режим подписки |
|---|---|---|---|
| Естественность речи | средняя | хорошая | очень высокая |
| Память об ошибках между уроками | структурированная (скилы) | нет, если не построить | общая память, без учёта ошибок |
| План урока, повторение слов | да | нет | нет, если не просить каждый раз |
| Выборочные исправления | управляемые | лучше, но непредсказуемые | хорошие, но бессистемные |
| Произношение | фонемный анализ (Mimora) | нет | на слух, без измерений |
| Читает файл урока, пишет паузы, ASR, аудио | да | нет | нет |
| Приватность и офлайн | полные | полные | нет |
| Стоимость | бесплатно после установки | железо | подписка; голосовые API дороги |

Вывод: подписка выигрывает по качеству разговора, но остаётся универсальным
собеседником без методики. Сильная сторона SpeakLoop не «ум» модели, а структура
урока и данные об ученике.

Гибрид (опция): разговор локально, разбор после урока одним запросом к облачной
модели. Стоит центы за урок, но транскрипт уходит в облако, поэтому только по
желанию пользователя.

---

## 12. Цикл целиком и связь с LoRA

```
файл урока (скилы)
   -> разговор (SpeakLoop)
   -> jsonl + аудио
   -> разбор (скилы) + произношение (Mimora)
   -> следующий файл урока
```

Скилы при разборе урока могут заодно отмечать **ошибки тьютора** (запрещённое
исправление, догадка, общее утверждение, выдумка в итогах) и писать правильный
ответ. Тогда набор данных для LoRA собирается сам, без отдельной разметки.

---

## 13. Набор для сравнения «до/после»

Нужен для любой меры из разделов 4 и 5.

- 30-50 фраз ученика из настоящих логов (с ошибками, без ошибок, команды, мусор
  распознавания) вместе с историей перед ними.
- Скрипт прогоняет их через llama-server с постоянным промптом.
- Автоматический подсчёт нарушений: NOTE-совпадение, NOTE на команду, `SAY:` в
  SUMMARY, язык SUMMARY, лишние строки. Смысловые нарушения (запрещённый тип
  исправления, догадка) размечает сильная модель или человек.
- Результат: таблица нарушений по типам для каждого варианта (температура,
  второй запрос, LoRA, другая модель).

## 14. Принятые решения

1. Роли частей системы (раздел 2): скилы для модели по подписке ведут память,
   оценку, создание уроков и разбор ошибок; SpeakLoop только разговор; Mimora
   произношение.
2. Формат jsonl транскрипта предназначен для связки со скилами и остаётся
   основой выхода.
3. Более мощная модель не рассматривается как предмет этой концепции (путь
   очевиден).
4. Проактивность нужна, вместе с кнопкой паузы.
5. Концепция фиксируется в этом документе; конкретные решения по реализации
   принимаются позже.
6. Решения по проактивности и паузе (2026-10-10/11) собраны в разделе 8.6:
   режим Space, все шаги лестницы, настройки `proactive` и
   `proactive_wait_seconds`, две скорости речи, правила таймера и паузы,
   деление на шаги P1, P2, P3.

Решения, принятые раньше и связанные с этой концепцией (из истории проекта):

- Тему урока выбирает программа: `first_topic` из настроек или случайная из
  большого списка; на «new topic» программа тоже выбирает тему; LESSON ARC
  запрещает модели менять тему самой.
- NOTE про команду убирается в коде из окна, транскрипта и истории модели, случай
  пишется в лог; промпт пока не меняется.
- Название темы в окне отложено до того, как программа знает тему.
- Кнопка Repeat запланирована, детали обдумываются позже.
